### Design decisions
- **Route binding = `{id}`** for all admin resources (matches arch doc literally: `/api/admin/professionals/{id}`, `/api/admin/portfolio/{id}`, `/api/admin/admins/{id}`). For Professional this overrides its global `#[RouteKey('slug')]` — controllers use `int $id` + `findOrFail()`.
- **Slug**: generated from `name` on store via `Str::slug($name)`, suffixed with a short random string if a collision is detected. **Never changed on update** (keeps public URLs stable — slugs aren't in `UpdateProfessionalRequest`).
- **Uploads**: `public` disk under `professionals/` (photos) and `portfolio/` (images/pdfs), filename = `StoredFile::put` generated name. On replace (update with new file) → delete old file. On professional delete → also delete cascaded portfolio-item files (DB cascades rows; files would orphan otherwise).
- **`service_id` for portfolio**: never set from client input. The `saving()` hook derives it. Controller just saves `professional_id` + media fields.
- **AdminUserController**: `superadmin` middleware; uses dedicated new Form Requests; password mass-assignment auto-hashes via the model's `hashed` cast; blocks self-deletion (403/422 with clear message).
- **RevalidationService**: env read via `config/services.php` (idiomatic, avoids raw `env()` in a class — same pattern as standard Laravel). Fires `Http::post()`; wrapped in try/catch that **logs failures but never throws**. Called after every successful store/update/destroy in both admin content controllers with tag arrays (matches arch doc's `revalidateTag` design). Sensible tags: `['talent']`, `['talent-{slug}']`, `['portfolio']`.
